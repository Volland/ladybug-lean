## Context

Release artifacts exist for every target: `liblbug-linux-x86_64.tar.gz`, `liblbug-osx-arm64.tar.gz` and `liblbug-windows-x86_64.zip`. Lean on Windows uses its bundled clang targeting the MinGW-w64 ABI, while the Ladybug DLL is built with MSVC. Ladybug's API is plain C, so the import library and the DLL are ABI-compatible at the C boundary.

## Goals / Non-Goals

**Goals:**
- One platform table in the lakefile, mapping (OS, arch) to the asset name, library file names and link flags.

**Non-Goals:**
- Linux and macOS aarch64/x86_64 variants beyond those three (the table makes adding them a one-line change).
- Static linking.

## Decisions

### Runtime loading instead of linking
The shim loads the library with `dlopen` (Unix, `RTLD_GLOBAL` so Ladybug's extensions can resolve its symbols) or `LoadLibraryA` (Windows) from the absolute path the build fetched, which is compiled in as `LBUG_LIB_PATH`; `LBUG_LIBRARY` overrides it at runtime. Every function is called through a pointer typed from `lbug.h` with `__typeof__` (`c/lbug_dyn.h`, generated by `scripts/gen-lbug-dyn.py`). Nothing links against Ladybug, so there is no rpath, no SONAME and no MSVC import library for MinGW clang to consume ([[decisions#Load Ladybug at runtime]]).

### Platform table
| Platform | Asset | Library file |
|---|---|---|
| macOS arm64 / x86_64 | `liblbug-osx-<arch>.tar.gz` | `liblbug.dylib` |
| Linux x86_64 / aarch64 | `liblbug-linux-<arch>.tar.gz` | `liblbug.so` |
| Windows x86_64 / arm64 | `liblbug-windows-<arch>.zip` | `lbug_shared.dll` |

`tar -xf` unpacks both archive kinds (bsdtar on macOS and Windows). On Windows the shim is compiled with Lean's bundled clang, since there is no system `cc`, and without `-fPIC`.

### CI
GitHub Actions matrix on `macos-14`, `ubuntu-latest` and `windows-latest`. `leanprover/lean-action` installs elan from `lean-toolchain` and runs `lake build` and `lake test`; `.lake/lbug` is cached by lock-file hash; the build-level checks run on macOS and Linux.

### Property tests with the project's own generators
Each column type has a one-column table, a seeded generator with edge cases (extreme integers, non-ASCII and empty strings, empty lists, NULLs, infinities, negative zero) and a shrinker. Values are compared bit for bit on both backends. Plausible was rejected because Lake has no test-only dependencies ([[decisions#Own generators for property tests]]).

## Risks / Trade-offs

- [MinGW clang cannot link the MSVC import library] → avoided entirely: the DLL is loaded at runtime.
- [Windows is not tested locally] → only CI exercises it; Linux was additionally verified in an Ubuntu 24.04 aarch64 container.
- [Ladybug release assets are renamed] → the platform table is the only place names appear; the fetch error says which asset was missing.
