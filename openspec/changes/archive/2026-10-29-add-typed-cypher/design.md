## Context

M1 provides `Value`, `FromValue`/`ToValue`/`FromRow`, and `LbugM` with prepared statements. This change adds the layers between a Lean program and those primitives. Three later changes reuse its core AST: the `cypher%` syntax (M3) elaborates into it, the ORM (M4) generates it, and the in-memory backend (M6) interprets it.

## Goals / Non-Goals

**Goals:**
- One untyped core AST that the printer, the syntax and the evaluator share.
- Types enforced when queries are built, at no runtime cost.
- Ordinary Lean ergonomics: dot notation, `do` blocks, no user-visible universe codes.

**Non-Goals:**
- Recursive paths, subqueries, UNION, vector and full-text search (M5).
- Proving properties of queries.

## Decisions

### Phantom-typed expressions over an untyped core
`Cypher.Core` is an untyped AST (`Expr`, `Pattern`, `Clause`, `Query`) whose literals are parameter references. The user-facing `Ladybug.Expr (α : Type) := ⟨Core.Expr⟩` is a phantom wrapper, and typed combinators are the only way to build one. This is the esqueleto pattern. Alternative rejected: an intrinsically typed GADT indexed by a type universe (lean-linq, FPIL). It is stronger, but it makes `cypher%` and the evaluator target a much larger type, and Cypher's dynamic semantics (NULL in every type, implicit coercions) fit a dynamically typed core better. Since both backends interpret `Value`s, M6 matches Ladybug's dynamic semantics directly.
- motivated_by:: [[decisions#Hybrid typed DSL]]

### Table metadata through type classes generated by commands
`node_table Person (key := id) (label := "Person")` and `rel_table WorksAt (from := Person) (to := Company)` are commands. They check the field types and generate:
- `NodeTable Person` / `RelTable WorksAt Person Company` instances with label, key and column list;
- `FromValue` / `ToValue` instances that decode from or encode to node properties;
- a companion `Person.Var` structure, one `Expr` field per property, built from a variable name, so `p.name` resolves by ordinary dot notation;
- `Person.Var.opt`, the same companion with every field wrapped in `Option`, used after OPTIONAL MATCH.

Alternative rejected: `deriving NodeTable`. Lean's `deriving` clauses take no arguments, so they cannot name the key, label or endpoints. A plain `deriving NodeTable` is still accepted as shorthand for the defaults.
- motivated_by:: [[decisions#Lean structures are the schema]]

### Nullability lifting with one class
`class Compat (α β : Type) (τ ρ : outParam Type)` holds when `α` and `β` are each `τ` or `Option τ`, with `ρ` the NULL-lifted result (`Option τ` if either operand is nullable). Binary operators take `Expr α` and `Expr β`. Comparisons always return `Expr (Option Bool)`, and arithmetic returns `Expr ρ`. Default instances make a literal whose type is still unknown take the other operand's type, so `p.age >. 30` checks `30` as an `Int64` ([[decisions#Literals typed from the other operand]]). `where_` takes either `Expr Bool` or `Expr (Option Bool)` through an `IsPred` class.
- motivated_by:: [[decisions#Full three-valued logic]]

### Builder monad
`QueryM := StateM BuilderState`, where the state holds the clause list, a fresh-name counter and the parameter list. `match_ (node Person) : QueryM Person.Var` appends a clause and returns the companion. Relationship patterns are `out p WorksAt (node Company)`, `inc …` and `both …`, whose `Matchable` instances check the endpoints ([[decisions#Pattern functions instead of arrow notation]]). `return_ (r : ρ) [Returnable ρ α] : QueryM (Ret α)`. Finally `query : QueryM (Ret α) → Query α`, and `stmt : QueryM Unit → Statement`. `Returnable` instances cover `Expr α`, table companions and tuples. `Query α` stores the core AST together with a `FromRow α` decoder.

### Single printer
`Cypher.Print` renders the core AST. Variables are `n<k>` and `r<k>` in clause order, parameters are `p<k>` in first-use order, and identifiers are backquoted unless they match `[A-Za-z_][A-Za-z0-9_]*`. The printer is pure and is tested with golden strings.

### MonadGraph
```lean
class MonadGraph (m : Type → Type) extends Monad m, MonadExceptOf Ladybug.Error m where
  runQuery  : Query α → m (Array α)
  runStmt   : Statement → m Unit
  withTx    : TxMode → m α → m α
  applySchema  : Schema → m Unit
  verifySchema : Schema → m (Array SchemaDiff)
```
The `LbugM` instance prints the query, keeps a per-connection `HashMap String PreparedStatement` cache, binds the parameters and decodes the rows. Schema verification reads `CALL show_tables()` and `CALL table_info('<T>')`.
- motivated_by:: [[decisions#Two backends one API]]

## Risks / Trade-offs

- [Phantom types can be bypassed through `Core`] → `Core` constructors stay public for the syntax and the evaluator, but they live in a namespace users do not open; the typed API never exposes them.
- [Instance search for `Lift` on nested `Option` is slow or ambiguous] → only `τ` and `Option τ` are supported; `Option (Option τ)` is rejected when a field is declared.
- [Ladybug's catalog procedures change output columns between releases] → verification decodes `show_tables` and `table_info` into `Value`, matching columns by name, and a test pins the expected shape.
